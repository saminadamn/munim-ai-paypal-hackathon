# Sponsor tools log

One line each time a sponsor tool helped or caused trouble (date, what happened, what we did).

- 2026-11-12 · PayPal AI Toolkit / APIMatic: plugins not available in the cloud build session, so invoicing endpoints (create, send, remind with its 2-per-day limit, partial_payment config) were confirmed against PayPal's published Invoicing v2 reference instead. Re-check with the APIMatic plugin locally.
- 2026-11-12 · AG Grid / AG Studio: started from PayPal's AG Grid hackathon boilerplate; its lib/paypal.ts (cached OAuth token, paging, retries) was extended with POST/PUT and per-call ApiLog logging rather than replaced.
- 2026-11-12 · AG Studio: the typed AI API (createAiHarness builder, directLlmRunner, api.defineAiTool, tools.delegateTo) let Munim run as a custom agent in Studio's assistant and hand chart work to the built-in lead/page/widget agents.
- 2026-11-12 · Render: wrote render.yaml (web + Postgres + Cron Job). The cron job reaches the web service over Render's private network using `fromService: property: hostport` and a generated CRON_SECRET shared via `envVarKey`, so no URL needs pasting. Tables are created by `prisma db push` in the start command (no pre-deploy hook needed).
- 2026-11-12 · Prisma (not a sponsor, but it affected the Render setup): Prisma 7 runs without a Rust query engine through @prisma/adapter-pg, which keeps the Render build simple. The cloud build sandbox couldn't download Prisma's schema engine or Google Fonts, so local verification used placeholders; Render downloads both normally.
- 2026-11-12 · AG Studio: the forecast chart is a one-widget, read-only AG Studio report (`line-chart`) instead of adding a chart library. Munim's forecast, client profiles and actions were added as Studio data sources with relationships to the boilerplate's customers and invoices, so the built-in agents can chart them when Munim delegates.
- 2026-11-12 · AG Grid: Community editors (NumberEditorModule, SelectEditorModule) made the invoice line items editable before approval; CellStyleModule colours the risk score.
- 2026-11-12 · PayPal docs (standing in for APIMatic in the cloud session): the brief said `configuration.allow_partial_payment`, but PayPal's invoice object nests it as `configuration.partial_payment.allow_partial_payment` with optional `minimum_amount_due`; built to the docs. Also confirmed `invoicer.email_address` must match the business account behind the credentials (now MERCHANT_EMAIL), the record-payment `method` enum, and that full update (PUT) takes `send_to_recipient`/`send_to_invoicer` query params defaulting to true, so updateInvoice turns both off unless asked.
- 2026-11-12 · Render: switched the start command from `prisma db push` to `prisma migrate deploy`, so the deployed schema comes from committed migrations.
- 2026-11-12 · PayPal docs: confirmed the payer link lives at `detail.metadata.recipient_view_url` (read back with GET after send), and that an invoice with a future issue date is scheduled rather than sent, so Munim keeps PayPal's invoice_date on the real calendar even when the demo clock is ahead.
- 2026-11-12 · AG Grid: the boilerplate's shared DataGrid gained an optional row-click side panel (needs RowStyleModule for the pointer cursor); the /invoices page uses it for each invoice's Munim timeline while the other endpoint pages are unchanged. The Inbox line items are an editable grid with invalid cells outlined.
- 2026-11-12 · AI SDK (not a sponsor): `generateObject` is deprecated in AI SDK 7 in favour of `generateText` with `output: Output.object(...)`; used the latter with the same zod schema. Requests go out as strict json_schema structured output.
- 2026-11-12 · PayPal docs: they document updating an invoice as GET then PUT of the full object (PUT drops omitted fields), but not whether a sent invoice accepts it. Munim's offer_partial therefore tries the full-object PUT and, if PayPal refuses, creates a replacement invoice with part-payment allowed, cancels the original, then sends the replacement (create first, so a failure never leaves the client with nothing to pay). To verify live: approve one offer_partial and check which path the activity log shows.
- 2026-11-12 · AG Grid: custom React cell renderers for status and guardrail badges in the activity log, plus QuickFilterModule for its search box.
- 2026-11-12 · Render: the cron job now authenticates with the `x-munim-key` header (MUNIM_CRON_KEY, generated in render.yaml and shared with the job via fromService envVarKey).
- 2026-11-12 · AG Studio custom widgets: registered "Munim today" and "Approval queue" through `createWidgets` (ag-studio-react) on the `widgets` prop, typed with a MunimRegistry. Typing the registry meant the data sources definition had to be typed for the same registry (`AgDataSourcesDefinition<MunimRegistry>`). Both widgets are data-less and read Munim's API, so the queue is live after an approval. The docs say a widget needs `formatShape` and `ai` for the assistant to place it; `formatShape` gets no shape builder in its params, so the widgets ship with `ai` metadata only and live in the default report.
- 2026-11-12 · AG Studio Agent Framework: `createAiHarness` builder with Munim as primary (`directLlmRunner` + `api.defineAiTool` client tools) and `builtIn.lead/data/page/planning/widget` spread with the same adapter, so Munim hands chart work to them with `tools.delegateTo`. Verified in a headless Chrome render: no Studio validation errors, prompt starters shown, the Reject button in the custom widget updates the queue. Dev mode shows "7 issues", which are the seven console lines of the trial-licence banner.
- 2026-11-12 · AG Studio theme: added borderRadius/buttonBorderRadius/inputBorderRadius and AI panel colours so Studio's controls match the app's pill buttons and 4px inputs.
- 2026-11-12 · PayPal webhooks: built against PayPal's verify-webhook-signature reference (the toolkit's webhooks.md wasn't available in the cloud session). The route returns 200 at once and verifies after the response with Next's after(); unverified events change nothing. PayPal's webhook simulator sends events that can't be verified, so the live test is a real sandbox payment. INVOICING.INVOICE.PAID also fires for part-payments and pending payments, so Munim re-reads the invoice and records one payment per paid amount.
- 2026-11-12 · Render: render.yaml now matches the brief (build runs `prisma migrate deploy`, health check /api/health, hourly cron curls /api/munim/run with x-munim-key). Prisma's Render guide runs migrations as a pre-deploy command instead; if the build can't reach the private database, switch to preDeployCommand (paid instances) as the comment in render.yaml says.
- 2026-11-12 · Render/Prisma: committed the first migration (prisma/migrations/20261112000000_init) so `prisma migrate deploy` in the Render build actually creates the tables; without it the deploy would start against an empty database.
